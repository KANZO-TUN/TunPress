# 実装計画・進捗管理ルール

カンゾーさんがエディタや Git 上でいつでも設計・進捗を確認できるよう、計画ドキュメントは一時フォルダではなくリポジトリ内に永続化する。

## 計画ドキュメントの作成
実装を伴う開発（機能開発・リファクタリング・バグ修正など）では、トピックブランチ作成後に以下を作成する。

- **ディレクトリ**: `plans/<ブランチ名>/`（`/` は `-` に置換）
  - 例: `feat/crawler-youtube` → `plans/feat-crawler-youtube/`
- **ファイル**:
  1. `implementation_plan.md` — 調査結果・設計案・検証計画
  2. `task.md` — 作業項目を細かく分解したチェックリスト

ドキュメントのみの変更や設定の微修正など、小さな作業では省略してよい。

**`plans/` は Public リポジトリで公開される。** 内部 IP・ホスト名・公開 URL・管理画面の所在などのインフラ詳細は書かず、「本番環境」「開発環境」などの一般名で表す（`git.md` の公開リポジトリのルールを参照）。

## 進捗の更新
- 作業中は `task.md` のチェックボックスをリアルタイムに更新する。
  - `[ ]` 未着手 / `[/]` 進行中 / `[x]` 完了
- 実装・テストの完了後、作業成果をまとめた `walkthrough.md` を同じディレクトリに作成する。

## 履歴の保存
- これらのドキュメントはソースコードと一緒にコミットし、PR に含める。設計意図とタスク分割をコミット履歴として残すため。
