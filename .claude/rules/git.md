# Git 運用ルール

## ブランチ
- `main` ブランチは保護されているため、直接 push しない。
- 必ずトピックブランチを作成し、PR 経由でマージする（マージ方式は **Squash のみ**）。
- 命名規則: `feat/機能名`, `fix/バグ名`, `chore/タスク名`, `refactor/対象名`

## コミットメッセージ
- タイトル先頭に小文字タグ＋コロン＋半角スペースを付与する: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`（`[refactor]` のような括弧形式は使わない）。
- タイトル・本文ともに **日本語のみ**、体言止めで簡潔に記述する。
- PR・Issue のタイトルも同じタグ形式で統一する。

## AI によるコミット・GitHub 操作の名義分離
カンゾーさんのローカル `git config` や `gh` ログイン（`KANZO-TUN`）を汚染しないため、AI が Git/GitHub を操作する際は認証情報を **コマンド単位の一時環境変数** で渡す。

- 認証情報の格納先: リポジトリ直下の `.secrets/github/`（gitignore 対象）
- `git config` を書き換えてはならない。具体的なコマンドは `github-ops` スキル参照。

## 実行タイミング
- コミット・push・PR 作成は、カンゾーさんから明示的な OK（承認）を得てから行う。

## 公開リポジトリとしての注意（重要）
`KANZO-TUN/TunPress` は **Public リポジトリ**。コミットした内容は、履歴も含めて全世界に公開される。

- **秘密情報**: API トークン・パスワード・`.env` 等は絶対にコミットしない。新しい機密ファイルを作る場合は先に `.gitignore` を更新する。
- **インフラ情報**: 内部 IP、公開 URL、管理画面（Portainer 等）の所在、Cloudflare Tunnel 名、開放ポートなど、攻撃の手がかりになる情報はコミットしない。必要な場合は「本番環境」「開発環境」などの一般名か、環境変数で表す。
- **個人情報**: カンゾーさん個人のキャリア・収入・プライベートに関わる内容はコミットしない。
- **非公開の置き場**: 上記を含む資料は `docs/`（gitignore 対象のローカル専用ディレクトリ）に置く。公開してよいファイルから `docs/` 内の情報を書き写さない。
- **コミット名義**: 作成者メールアドレスも公開されるため、GitHub の noreply アドレス（`<ID>+<ユーザー名>@users.noreply.github.com`）を使う。

## push・PR 作成前のセキュリティ監査（必須）
- `git push` や PR の作成・更新の前に、必ず `security` サブエージェントで今回の差分（`git diff`）を監査する。
- 「公開リスクなし」の判定、または指摘事項への対策完了を確認するまで push しない。
