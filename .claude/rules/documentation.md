# ドキュメント保守ルール

## 自律的な更新
- ディレクトリ構成・コマンド・運用ルール・前提知識などが変わったら、`README.md`・`CLAUDE.md`・`.claude/rules/`・`docs/` の更新が必要かを自ら判断し、言われる前に同期する。
- 規約は1か所にだけ書く（正本の一元化）。同じ内容を複数ファイルに重複させない。

## PR 前の整合性チェック
- PR の作成・更新前に、実装が `README.md` や各ドキュメント内のパス・構成に影響していないか確認し、以下を実行する。
  ```bash
  python3 .claude/skills/github-ops/scripts/check_readme.py
  ```
- 不整合が出た場合は、ドキュメントを修正してから PR を作成・更新する。

## 公開ドキュメントと非公開ドキュメント
| 置き場 | 公開 | 用途 |
| :--- | :--- | :--- |
| `README.md`, `CLAUDE.md`, `.claude/`, `plans/` | **Public** | 公開して問題のない情報のみ |
| `docs/`（`docs/export/` を含む） | 非公開（gitignore 対象） | インフラ詳細・企画・個人的な情報を含む資料 |

- 公開ファイルから `docs/` 内のファイルへリンクを張らない（GitHub 上ではリンク切れになり、非公開資料の存在も知らせてしまうため）。

## `docs/` の書式（Obsidian 形式）
`docs/` はカンゾーさんの Obsidian Vault と同期して読む前提のため、以下の書式を維持する。

- 先頭に YAML フロントマター（`執筆者`, `作成日時`, `更新日時`, `tags`）を置く。
  - 新規作成時の `執筆者` は `クラウド`。既存ドキュメントの `執筆者` は変更しない。
  - 編集時は `更新日時` を `YYYY-MM-DD HH:MM` 形式で更新する。
- タイトルはファイル名で表示されるため、本文の見出しは `##` から始める。
- ドキュメント間のリンクは Obsidian のウィキリンク `[[ファイル名]]` を使う。
