# プルリクエスト＆レビュー運用ルール

具体的な `gh` コマンド手順は `github-ops` スキルを参照。

## PR 本文テンプレート
PR を作成・更新する際は、本文に必ず以下の見出しを含める。

````markdown
## 概要
[一言でどんな機能か、またはリファクタリングの目的]

## 実装内容
- [施した処理・修正を箇条書き]
- [追加・変更したコンポーネント]

## ユニットテスト結果
- [テストの種類・実行コマンド・結果。存在しない場合は「なし」と明記]

## AI確認箇所
- [Cloud が実装中に実際に行った動作確認・構文チェックの内容]

## 動作確認依頼 (手動テストシナリオ)
- [カンゾーさんに実施してほしい手順を、コマンドと期待結果つきで記述]
````

- cron や常駐デーモンなどのバックグラウンド処理を追加・変更する PR では、手動テストシナリオに **「1分後の結合テスト手順」**（スケジュールを一時的に1分後へ変更 → ログ監視 → 元に戻す）を必ず含める。

## レビュアー
- PR 作成後は必ず `KANZO-TUN` をレビュアーとしてアサインする。

## 進捗ステータスラベル
PR には常に「現在のフェーズ」のラベルを1枚だけ貼る。次のフェーズに進む際は、前のラベルを外してから次のラベルを貼る。

| ラベル | 状態 | 担当 |
| :--- | :--- | :--- |
| `1.unit-test-passed` | 実装完了、ユニットテスト・構文チェックをパス | Cloud |
| `2.needs-review` | カンゾーさんへレビュー依頼済み（放置防止のための最重要ラベル） | カンゾーさん |
| `3.integration-test-passed` | コードレビュー・手動結合テスト完了 | カンゾーさん |
| `4.needs-prod-check` | 本番デプロイ済み、本番での動作（自動実行含む）を確認中 | システム |
| `5.prod-check-passed` | 本番確認完了、マージ準備完了 | 全員 |
| `hold` | 保留（順番とは独立して随時付与） | 全員 |

## レビューコメントへの対応
- **スレッド返信**: レビューコメントには、必ずそのコメントへのスレッド返信で答える。PR 全体へのコメントや新規インラインコメントとして返信しない。
- **指摘ごとのコミット分割**: 1つのコミットに複数の指摘への修正を混在させず、指摘（スレッド）単位で個別にコミットする。
- **修正コミットのリンク**: 返信には対応コミットを GitHub URL リンク形式で記載し、ワンクリックで差分を確認できるようにする。
  - 例: `[abcdef1](https://github.com/KANZO-TUN/TunPress/commit/abcdef1...)`
