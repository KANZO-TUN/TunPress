# 設計手順（TunPress）

実装前に意図のすり合わせと安全設計を済ませ、本番環境の破壊やデプロイミスを防ぐための手順。

## 1. ヒアリング
- 要件・方向性に曖昧な点があれば、実装に進む前にカンゾーさんに確認する。
- 確認では選択肢と推奨案を示し、判断材料（メリット・デメリット・学習面での価値）を添える。
- 合意した内容は `implementation_plan.md` に記録する。

## 2. 既存設計との突き合わせ
- `docs/03_要件定義.md`（要件）、`docs/04_設計書.md`（DB スキーマ・技術スタック）、`docs/01_環境構築.md`（インフラ）と矛盾しないかを確認する。
- 設計書の変更が必要な場合は、その変更自体も計画に含める。

## 3. 安全設計（Safety Guard）
システム変更・インフラ変更では、以下を計画に必ず含める。
- **リスク分析**: 何が壊れうるか、影響範囲（本番環境 / 開発環境 / 永続データ）
- **事前確認**: バックアップの有無、開発環境でのドライラン手順
- **ロールバック手順**: 動かなかった場合に元へ戻す具体的なコマンド

## 4. 可視化
- 構成・データフロー・画面遷移は Mermaid 図で示す（`flowchart`, `sequenceDiagram`, `erDiagram` など）。

## 5. 計画ドキュメントの作成
- `.claude/rules/planning.md` に従い、`plans/<ブランチ名>/` に `implementation_plan.md` と `task.md` を作成する。
- `implementation_plan.md` の構成例:
  ```markdown
  ## 目的
  ## 前提・調査結果
  ## 設計（図を含む）
  ## リスクとロールバック
  ## 検証計画（ユニットテスト / 手動テストシナリオ）
  ```
